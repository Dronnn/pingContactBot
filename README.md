# Контакт для вещи

Telegram-бот со ссылками и QR для машины, рюкзака, двери, объявления или отдельной темы. Посетитель пишет боту в личку, а владелец вещи или участники группы отвечают через бота. Личные профили и телефоны автоматически не передаются.

Проект реализован для **Telegram Serverless**, CLI **0.2.0**. Обработчики, база SQLite и отправка сообщений работают на стороне Telegram. Собственный сервер, внешний QR API, ИИ и постоянно запущенный процесс не нужны.

**Статус:** исходники готовы, локальная проверка выполнена. На реальном аккаунте Telegram бот ещё не развёрнут. Для запуска нужны твой бот и его Serverless CLI Access token.

## Что готово

- Несколько личных контактов и несколько общих контактов группы.
- Название и короткое публичное описание каждой карточки.
- Непредсказуемая ссылка: 24 случайных байта, без Telegram ID внутри.
- QR-картинка и PNG-файл для печати; генерация внутри проекта без сетевого QR-сервиса.
- Двусторонняя текстовая переписка с отдельным номером каждого диалога.
- Ответ кнопкой, обычным Reply на сообщение бота или командой `/reply`.
- Список контактов, список диалогов, постраничная навигация.
- Отключение и повторное включение карточки.
- Замена ссылки: старый QR и прежние диалоги перестают принимать сообщения.
- Удаление карточки с отзывом доступа и очисткой её публичного названия/описания.
- Блокировка и разблокировка посетителя для всех карточек одного владельца или группы.
- Завершение диалога. Посетитель может отключить ответы; владелец не может отменить его решение.
- Общие контакты группы, поддержка тем и перенос уведомлений через `/move`.
- Ограничения частоты, проверка прав при каждом действии, защита от повторных updates.
- Русские команды, inline-кнопки и адресные формы ForceReply.

## Быстрый запуск

### 1. Создай бота и включи Serverless

В [@BotFather](https://t.me/BotFather):

1. Создай нового бота командой `/newbot`.
2. Открой настройки этого бота → **Serverless** и включи его.
3. Открой **CLI Access → Access token**.

Для `tgcloud login` нужен именно **Serverless CLI Access token** вида `app<id>:<secret>`. Обычный Bot API token сюда не подходит. Не вставляй токен в исходники или переписку; введи его в приглашение CLI.

Для первого запуска используй отдельного нового бота: `push` синхронизирует его набор обработчиков с этим проектом. Если выбран существующий бот, сначала сохрани его текущий проект.

### 2. Установи зависимости и CLI

На компьютере нужен **Node.js 24 или новее**. Этот минимум относится к локальным проверкам проекта; в облаке Node.js не запускается.

В терминале, из корня репозитория:

```bash
npm ci
npm run verify
npx tgcloud login
npx tgcloud push
npx tgcloud migrate
```

`login` попросит CLI Access token. `migrate` покажет создание таблиц и попросит подтвердить изменение базы. `init` и генератор нового проекта не нужны.

Код и схема публикуются через `push`, применение схемы — отдельный шаг `migrate`. До завершения обоих шагов не начинай пользоваться ботом.

В ZIP нет учётных данных. CLI хранит их в локальной папке `.tgcloud/`, уже исключённой из Git. Публикуются только JS-файлы внутри `tgcloud/`; тесты и страница печати остаются на компьютере.

### 3. Инициализируй меню

Открой бота в Telegram и отправь:

```text
/start
/setup
```

Бот установит команды для личек и групп. `/setup` проверяет доступ к базе, права в группе и наличие безопасного генератора ссылок в среде выполнения.

Затем создай первый контакт:

```text
/new Моя машина
```

Придут карточка со ссылкой и QR. Для несжатого PNG нажми **QR для печати**.

## Как пользоваться в личке

1. Владелец создаёт «Моя машина» и размещает QR под стеклом.
2. Посетитель сканирует QR, открывает бота и нажимает **Start / Запустить**, если Telegram этого попросит.
3. Бот показывает название, описание и адресата. Посетитель пишет: «Вы перекрыли выезд».
4. Владельцу приходит новое сообщение: `По поводу «Моя машина» · Собеседник #12`.
5. Владелец отвечает через Reply или кнопку **Ответить**: «Выхожу».
6. Посетитель получает ответ от имени контакта.

После открытия ссылки посетитель может отправить несколько текстовых сообщений. Выход через `/cancel`, просмотр меню, другой карточки или списка диалогов отменяет активный ввод. Чтобы продолжить позднее, нужно открыть диалог и нажать **Написать**.

Кнопка **Ответить** открывает форму. Отвечай именно на запрос бота через Reply; форма привязана к тебе, чату и конкретному сообщению. Это предотвращает случайную отправку не тому собеседнику.

## Как пользоваться всей группой

1. Добавь бота в группу кнопкой **Добавить в группу** из его личного меню.
2. Назначь бота администратором. Дополнительные права на удаление сообщений, приглашение людей или повышение участников проекту не нужны.
3. Администратор группы отправляет `/setup`, затем `/new Дверь мастерской`.
4. Разместите QR или ссылку. Посетитель всегда пишет в **личку боту**.
5. Обращение поступает в группу. Участник может ответить обычным Reply или кнопкой **Ответить**.

Карточка принадлежит **группе**, а не человеку, создавшему её. Уход создателя не передаёт и не удаляет карточку. Посетитель видит публичное название контакта, но не получает автоматически название группы, ссылку на неё или профили ответивших участников.

| Действие | Участник группы | Администратор группы |
|---|---:|---:|
| Смотреть контакты и диалоги | Да | Да |
| Получать обращения в чат | Да | Да |
| Отвечать собеседнику | Да, при наличии права писать | Да |
| Создавать и менять карточки | Нет | Да |
| Отключать, удалять, заменять ссылки | Нет | Да |
| Блокировать и разблокировать | Нет | Да |
| Завершать или возобновлять общий диалог | Нет | Да |

Обычные сообщения группы никуда не передаются. Автоматическая отправка следующего свободного сообщения в группе не используется: нужен Reply на обращение или на адресный запрос бота. Права проверяются снова при отправке, даже если кнопка или форма были открыты раньше.

Для проверки текущего членства бот должен быть администратором. Отдельно отключать Privacy Mode в BotFather для этого режима не требуется. Если в группе несколько ботов, используй команды с адресом: `/contacts@имя_бота`.

**Темы:** карточка, созданная в теме, получает обращения туда. Для переноса администратор открывает нужную тему и пишет `/move 3`, где `3` — номер карточки. При недоступной теме бот сообщает об ошибке; он не переносит обращение молча в другую тему.

Команды от имени канала или анонимного администратора не принимаются как действия конкретного человека. Для ввода и ответов используй свой аккаунт.

## Команды

| Команда | Назначение |
|---|---|
| `/start` | Главное меню; ссылки вещей используют её служебный параметр |
| `/new Моя машина` | Создать карточку с названием |
| `/new` | Создать карточку через форму |
| `/contacts` | Карточки текущего владельца или группы |
| `/inbox` | Список диалогов; в личке включает собственные обращения к чужим вещам |
| `/reply 12 Выхожу` | Отправить текст в диалог №12 после проверки доступа |
| `/reply 12` | Открыть форму ответа в этот диалог |
| `/blocked` | Список блокировок и разблокировка |
| `/move 3` | Перенести уведомления карточки №3 в текущую тему группы |
| `/cancel` | Отменить только свой текущий ввод |
| `/help` | Инструкция внутри Telegram |
| `/privacy` | Какие данные видны и что сохраняется |
| `/setup` | Обновить меню и проверить подключение |

Остальные операции выполняются кнопками карточки: **QR-код**, **QR для печати**, **Название**, **Описание**, **Отключить / Включить**, **Заменить ссылку**, **Удалить карточку**. Для удаления, замены ссылки, блокировки и завершения диалога есть подтверждение.

## Разница между отключением, заменой и блокировкой

| Операция | Результат |
|---|---|
| Отключить | Переписка останавливается в обе стороны; повторное включение сохраняет прежний QR |
| Заменить ссылку | Выдаётся новый QR; старые ссылки, сессии и диалоги этого поколения больше не передают сообщения |
| Заблокировать собеседника | Закрывается доступ по всем карточкам этого владельца или группы; смена ссылки блок не снимает |
| Завершить владельцем | Диалог закрывается; это организационное действие, посетитель может снова его открыть |
| Завершить посетителем | Ответы ему отключаются; возобновить переписку может сам посетитель |
| Удалить карточку | Публичные название/описание стираются, ссылка отзывается; сообщения в Telegram не удаляются |

Посетителю не показывается отдельное уведомление «вас заблокировали». Он получает общий ответ о недоступности контакта.

## Печать наклеек

Открой `tools/print-qr.html` обычным двойным кликом в браузере. Вставь ссылку из карточки бота, введи надпись и выбери число копий. Страница работает без интернета, не загружает внешние скрипты и никуда не отправляет ссылку.

Есть предварительный просмотр, печать на A4 и скачивание PNG. QR использует коррекцию ошибок Q и белые поля в четыре модуля. После печати проверь код телефоном до размещения на вещи. Поля вокруг QR не обрезай.

Настройки находятся в `tgcloud/lib/config.js`:

| Ограничение | По умолчанию |
|---|---:|

| Создание карточек | 5 в час на чат |

| Отправка посетителем | 5 в минуту, 30 в час |

Для старого сообщения без действующего Reply-маршрута используй кнопку **Ответить** или `/inbox`. Фото, голосовые, файлы, геопозиции и карточки контактов не передаются. Каналы не поддерживаются; доступны лички, группы и супергруппы. Пользователю нужен Telegram и доступ к боту.

## Данные и доставка

Бот создаёт новые сообщения через `sendMessage`. Он не копирует `from`, `forward_origin`, имя, username, подпись автора или исходные `entities`. Если человек сам написал телефон или ссылку в тексте, получатель увидит их.

Это скрытие контактов друг от друга, без обещания полной анонимности. Telegram обрабатывает сообщения, владелец бота имеет технический доступ к его базе. В группе обращение доступно участникам чата.

В SQLite сохраняются карточки, Telegram ID, связи диалогов, блокировки, формы, маршруты и технические статусы доставки. Тексты переписки в таблицы не записываются. Они остаются в Telegram у участников. Просроченные технические записи удаляются ограниченными порциями при обращениях; без активности физическое удаление откладывается. После удаления карточки остаётся техническая запись без её публичного названия и описания, а также служебные связи. Полного удаления аккаунта одной командой в этой версии нет.

Повтор одного и того же update не отправляет текст повторно. При сетевой неопределённости бот прямо пишет, что сообщение могло прийти; автоматического повтора нет. Абсолютную гарантию «ровно один раз» между SQLite и Telegram Bot API дать нельзя. Если обработчик оборвался после регистрации события, действие может потребовать нового явного запроса пользователя. Незавершённые доставки не переотправляются таймером.

При удалении бота или потере административных прав контакты группы отключаются. После возврата бота администратор включает их вручную. Миграция группы в супергруппу переносит карточки и блокировки; старые Reply-связи отзываются. Незавершённый перенос можно продолжить через `/setup` в новом чате.

## Проверки и текущие границы проверки

Проверено **52 теста, 52 успешно**, включая независимое декодирование QR через ZXing. Есть положительные сценарии лички/группы и отрицательные проверки доступа: другой пользователь, потеря роли, чужая форма, несколько диалогов, старый QR, блокировки, отключение, повторы, миграция, ошибки `403`, `429` и неопределённая доставка.

Базовый запуск:

```bash
npm run verify
```

Без Python этот запуск выполняет 51 проверку, а независимое декодирование QR явно пропускается. Полный запуск описан в `tests/QR_TESTING.md`.

Тесты используют настоящую локальную SQLite и подставной Bot API. Они проверяют SQL, маршрутизацию, права и поведение кода; это не сетевой прогон на Telegram Serverless. Страница печати проверена исполнением её встроенного QR-движка, PNG отдельно декодированы; снимок интерфейса браузера не делался.

Наличие `crypto.getRandomValues` подтверждено измерениями автора адаптера `@aiogram/tgcloud-grammy`, но не перечислено отдельной гарантией в официальной SDK-справке. Поэтому `/setup` проверяет доступность, а создание ссылки прекращается при её отсутствии. Предсказуемый `Math.random` в качестве замены не используется. Перед печатью первых наклеек сделай один настоящий обмен сообщениями через два Telegram-аккаунта.
